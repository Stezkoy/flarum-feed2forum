# Feed2Forum

![License](https://img.shields.io/badge/license-MIT-blue.svg)

Расширение для Flarum 2.x, которое превращает RSS/Atom-ленты в **настоящие темы форума**: каждая загруженная статья становится обычной темой Flarum, созданной выбранным в настройках пользователем и с тегами, привязанными к ленте.

[Читать документацию на английском](readme.md)

## Возможности

- Загружает RSS/Atom источники по расписанию и сразу публикует каждую новую статью как **настоящую тему Flarum** (без виртуальных страниц и отложенного создания).
- Один **глобальный пользователь-автор** для всех импортированных тем — задаётся один раз в админке.
- **До двух тегов привязывается к каждой ленте** (один основной + один второстепенный) — импортированные темы автоматически попадают в эти теги. Выбор — через штатный диалог.
- Дата создания темы берётся из **даты публикации статьи в ленте**.
- **Per-feed лимит публикаций**: за одну проверку публикуется только N самых свежих новых статей (0 = без лимита).
- **Per-feed режим публикации**: выбрать для каждой ленты один из двух вариантов:
  - **Автоматически** — новые статьи публикуются сразу.
  - **Вручную** — статьи ждут в очереди в админке, пока вы не опубликуете каждую одним кликом.
- Интервал проверки задаётся в **минутах** (по умолчанию 60) и применяется через планировщик.
- Кнопка **Проверить ленту** для каждой ленты и общая кнопка **Проверить все ленты** для ручного запуска загрузки в любой момент.
- **Ссылка на оригинальную статью** в начале каждого импортированного поста (можно отключить глобально).
- Предпросмотр ленты в админке — лента загружается в реальном времени.
- Дедупликация по GUID/ссылки — ничего не импортируется дважды; заголовки, содержимое и даты обновляются при повторной загрузке.
- Пауза любой ленты одним переключателем — приостановленные ленты пропускаются при загрузке.
- Тяжёлая работа (загрузка лент и создание тем) выполняется как **джобы очереди** (`Flarum\Queue`) — большое количество постов не останавливает форум.
- Английская и русская локали.

## Требования

- Flarum `^2.0`
- PHP `^8.3`
- `flarum/tags` (устанавливается автоматически как зависимость)
- Composer

## Установка

Установите с помощью Composer:

```sh
composer require stezkoy/flarum-feed2forum
php flarum migrate
php flarum cache:clear
```

Включите **Feed2Forum** в админ-панели Flarum.

## Настройка в админке

Откройте страницу **Feed2Forum** в админ-панели.

### Общие настройки

- **Автор** — пользователь, от имени которого создаются импортированные темы. Можно выбрать любого пользователя, сменить или отвязать.
- **Частота проверки (минуты)** — как часто планировщик запускает загрузку лент (по умолчанию 60 минут).
- **Ручное подтверждение публикации** — если включено, статьи не публикуются автоматически; одобряйте их по одной в очереди ниже.
- **Добавлять ссылки на оригинал** — показывать или скрывать ссылку «Оригинальная статья» в начале каждого импортированного поста (включено по умолчанию).

### Ленты

Каждая строка таблицы **Ленты** редактируется на месте и сохраняется при потере фокуса:

- **Название** и **URL** ленты.
- **Тег** — до двух тегов (основной + второстепенный), в которые публикуются импортированные темы (открывается штатным диалогом выбора тега).
- **Лимит публикаций** — сколько самых свежих новых статей сохраняется/публикуется за одну проверку (пусто = 5, 0 = без лимита). В ручном режиме это же число ограничивает количество статей, попадающих в очередь на одобрение за одну проверку.
- **Публикация** — per-feed режим: *Автоматически* или *Вручную* (очередь на одобрение).
- **Статус** — переключатель паузы/возобновления ленты.
- Действия — **Проверить ленту**, **Предпросмотр** (загрузить ленту в реальном времени) и **Удалить**.

Новые ленты добавляются через пустую строку внизу таблицы.

### Очередь на одобрение

Ленты в режиме **Вручную** отправляют новые статьи сюда: публикуйте любую одним кликом (тема создаётся сразу, статья уходит из очереди), удаляйте по одной или очистите всю очередь кнопкой.

## Загрузка лент

Расширение регистрирует команду `feed2forum:fetch`.

Загрузить все активные ленты:

```sh
php flarum feed2forum:fetch
```

Проверить отдельный URL без сохранения:

```sh
php flarum feed2forum:fetch "https://example.com/feed.xml"
```

Команда **ничего не загружает сама**: она отправляет по одному `FetchFeedJob` на каждую активную ленту в очередь Flarum. Каждая джоба читает ленту, сохраняет новые статьи и (в автоматическом режиме) отправляет `PublishItemJob`, которые создают темы. Кнопка «Опубликовать» в очереди админки работает так же.

То есть загрузка лент и создание тем выполняются воркером очереди, а не планировщиком и не веб-запросом:

```sh
php flarum queue:work
```

С дефолтным драйвером `sync` каждая джоба выполняется inline, и расширение работает из коробки — но при большом количестве лент или постов настройте настоящую очередь (database/Redis) и запустите воркер.

Команда выполняется с интервалом, выбранным в настройках, через планировщик Flarum. Убедитесь, что планировщик Flarum запущен на сервере, например:

```sh
* * * * * cd /path/to/flarum && php flarum schedule:run >> /dev/null 2>&1
```

## Как это работает

Все шаги ниже выполняются асинхронно через очередь Flarum (дефолтный драйвер: sync).

1. При каждом запуске фетчер читает **активные** ленты.
2. Новые статьи (ранее не встречавшиеся, дедупликация по GUID/ссылке) сохраняются с датой публикации из RSS.
3. Существующие статьи обновляются по заголовку/содержимому/дате и не импортируются повторно.
4. В режиме **auto** до *лимита публикаций* самых свежих новых статей сразу превращаются в темы.
5. В режиме **queue** автоматически ничего не публикуется — одобряйте статьи из админки.
6. Каждая тема получает:
   - дату публикации статьи из RSS как дату создания темы,
   - содержимое, преобразованное из HTML (абзацы, списки, изображения, ссылки), и ссылку на оригинал,
   - выбранного в настройках глобального автора,
   - теги ленты (вместе с родительскими тегами).
