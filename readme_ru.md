# Feed2Forum

![License](https://img.shields.io/badge/license-MIT-blue.svg) [![Latest Stable Version](https://img.shields.io/packagist/v/stezkoy/flarum-feed2forum.svg)](https://packagist.org/packages/stezkoy/flarum-feed2forum) [![Total Downloads](https://img.shields.io/packagist/dt/stezkoy/flarum-feed2forum.svg)](https://packagist.org/packages/stezkoy/flarum-feed2forum)

Расширение для Flarum 2.x, которое превращает RSS/Atom-ленты в **настоящие темы форума**: каждая загруженная статья становится обычной темой Flarum, созданной выбранным в настройках пользователем и с двумя тегами, привязанными к ленте.

[English version](readme.md)

## Возможности

### Настоящие темы из лент
- Загружает RSS/Atom источники по расписанию и сразу публикует каждую новую статью как настоящую тему Flarum.
- Один **глобальный пользователь-автор** для всех импортированных тем — задаётся один раз в админке.
- Дата создания темы берётся из **даты публикации статьи в ленте**.
- Содержимое преобразуется из HTML (абзацы, списки, изображения, ссылки) в формат Flarum.

### Ленты
- **До двух тегов** (основной + второстепенный) на ленту — импортированные темы попадают в эти теги вместе с родительскими. Выбор — через штатный диалог Flarum.
- **Per-feed лимит публикаций**: за одну проверку сохраняется только N самых свежих новых статей (0 = без лимита). В ручном режиме это же число ограничивает очередь одобрения.
- **Per-feed режим публикации**: *Автоматически* или *Вручную* (очередь одобрения).
- Пауза любой ленты одним переключателем — приостановленные ленты пропускаются при загрузке.
- Предпросмотр ленты в админке — лента загружается в реальном времени.

### Очередь одобрения и безопасность
- **Ручная очередь одобрения** — статьи ждут в админке, пока вы не опубликуете каждую одним кликом (тема создаётся сразу).
- Восстановленные статьи, чья тема была удалена с форума, возвращаются с бейджем **«Ранее удалена»** и никогда не публикуются автоматически — решение за вами.
- Пропущенные статьи остаются в базе как «надгробия» и больше не импортируются.
- Дедупликация по GUID/ссылке — ничего не импортируется дважды.
- Кнопки **очистки всей очереди** и **проверки всех лент** по требованию.

### Журнал работы
- Сворачиваемый журнал под очередью: загрузки, публикации, пропуски и ошибки.
- В базе хранится не более 500 записей (обрезается при каждой записи), админка грузит только последние 100.

### Производительность и эксплуатация
- Тяжёлая работа (загрузка лент и создание тем) выполняется как **джобы очереди** (`Flarum\Queue`).
- Интервал проверки задаётся в **минутах** (по умолчанию 60) через планировщик Flarum.
- Опциональная **ссылка на оригинальную статью** в начале каждого импортированного поста (можно отключить глобально).
- Английская и русская локали.

## Требования

- Flarum `^2.0`
- PHP `^8.3`
- `flarum/tags` (устанавливается автоматически как зависимость)

## Установка

```bash
composer require stezkoy/flarum-feed2forum
php flarum migrate
php flarum cache:clear
```

Включите **Feed2Forum** в админ-панели Flarum.

## Обновление

```bash
composer update stezkoy/flarum-feed2forum
php flarum migrate
php flarum cache:clear
```

## Настройка в админке

Откройте **Админ → Расширения → Feed2Forum**.

### Общие настройки
- **Автор** — пользователь, от имени которого создаются импортированные темы. Можно выбрать любого пользователя, сменить или отвязать.
- **Частота проверки (минуты)** — как часто планировщик запускает загрузку лент (по умолчанию 60 минут).
- **Добавлять ссылки на оригинал** — показывать или скрывать ссылку «Оригинальная статья» в начале каждого импортированного поста (включено по умолчанию).

### Ленты
Каждая строка таблицы **Ленты** редактируется на месте и сохраняется при потере фокуса:
- **Название** и **URL** ленты.
- **Тег** — до двух тегов (основной + второстепенный), в которые публикуются импортированные темы (открывается штатным диалогом выбора тега).
- **Лимит публикаций** — сколько самых свежих новых статей сохраняется за одну проверку (пусто = 5, 0 = без лимита).
- **Публикация** — per-feed режим: *Автоматически* или *Вручную* (очередь одобрения).
- **Статус** — переключатель паузы/возобновления ленты.
- Действия — **Проверить ленту**, **Предпросмотр** (загрузить ленту в реальном времени) и **Удалить**.

Новые ленты добавляются через пустую строку внизу таблицы. Кнопка **Проверить все ленты сейчас** (справа сверху) запускает ручную проверку всех активных лент.

### Очередь одобрения
Ленты в режиме *Вручную* отправляют новые статьи сюда: публикуйте любой кликом, скрывайте или очищайте всю очередь сразу. Восстановленные статьи помечены бейджем «Ранее удалена».

### Журнал работы
Сворачиваемый журнал под очередью: загрузки, публикации, пропуски и ошибки. Обновляется и очищается кнопками тулбара.

## Загрузка лент

Расширение регистрирует команду `feed2forum:fetch`.

Загрузить все активные ленты:

```bash
php flarum feed2forum:fetch
```

Проверить отдельный URL без сохранения:

```bash
php flarum feed2forum:fetch "https://example.com/feed.xml"
```

Команда **ничего не загружает сама**: она отправляет по одному `FetchFeedJob` на каждую активную ленту в очередь Flarum. Каждая джоба читает ленту, сохраняет новые статьи и (в автоматическом режиме) отправляет `PublishItemJob`, которые создают темы.

С дефолтным драйвером `sync` каждая джоба выполняется inline, и расширение работает из коробки — но при большом количестве лент или постов настройте настоящую очередь (database/Redis) и запустите воркер:

```bash
php flarum queue:work
```

Команда выполняется с интервалом, выбранным в настройках, через планировщик Flarum. Убедитесь, что планировщик Flarum запущен на сервере, например:

```bash
* * * * * cd /path/to/flarum && php flarum schedule:run >> /dev/null 2>&1
```

## Как это работает

Все шаги ниже выполняются асинхронно через очередь Flarum (дефолтный драйвер: sync).

1. При каждом запуске фетчер читает **активные** ленты.
2. Новые статьи (ранее не встречавшиеся, дедупликация по GUID/ссылке) сохраняются с датой публикации из RSS.
3. Существующие статьи обновляются по заголовку/содержимому/дате и не импортируются повторно.
4. Статьи, чьи темы удалены с форума, возвращаются в очередь с бейджем «Ранее удалена» (только ручное одобрение).
5. В режиме **Автоматически** до *лимита публикаций* самых свежих новых статей сразу превращаются в темы.
6. В режиме **Вручную** автоматически ничего не публикуется — одобряйте статьи из админки.
7. Каждая тема получает:
   - дату публикации статьи из RSS как дату создания темы,
   - содержимое, преобразованное из HTML (абзацы, списки, изображения, ссылки), и ссылку на оригинал,
   - выбранного в настройках глобального автора,
   - теги ленты (вместе с родительскими тегами).
